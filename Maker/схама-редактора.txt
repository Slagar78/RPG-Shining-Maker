Правила работы с subAreas:
• Main — всегда есть, редактируется, удалить нельзя
• Sub — до 10 штук, можно добавлять/удалять
• «+ Add» — создаёт 2×2 в центре карты
• Поля Sub активны, только если выбран элемент списка
• Только цифры (фильтр через Tunnel-подписку на TextInputEvent)


📁 Формат areas.json

Без subAreas (старые карты, работают как есть):
[{"mainLayerStart":[0,0],"mainLayerEnd":[50,31]}]

С subAreas (красивый формат через StringBuilder):
[{
  "mainLayerStart": [0,0],
  "mainLayerEnd": [50,31],
  "subAreas": [
    { "start": [3,5],  "end": [10,12] },
    { "start": [7,5],  "end": [17,19] }
  ]
}]

• Обратная совместимость: старый формат — работает
• Максимум 10 sub-areas (индексы 0..9)
• Порядок строк = порядок sub-areas
• При записи — каждая subArea в одну строку (красиво)

🎮 Что изменилось в игре (Ruby-движок)

Файл game.rb
• Камера/маска — обновлено:
  - после EndMode2D() рисуется 4 чёрных полосы вокруг активной area
  - если игрок в main — маска = main bounds
  - если игрок в subArea — маска = subArea bounds
  - если area меньше экрана — камера центрирует её
• Warp (events.json) — обработка line-режима:
  - если "mode": "line" — срабатывает на любой тайл в прямоугольнике trigger_x/y → end_x/y

Файл GameMap.rb
• attr_reader :sub_areas
• Парсинг subAreas из areas.json (максимум 10)
• Новый метод inside_any_area?(x, y) — main ИЛИ любая subArea
• Новый метод area_bounds_for(x, y) — bounds той area, где сейчас игрок
  (если в subArea — её, если в main — main)

Файл player.rb
• try_move_or_turn использует inside_any_area? вместо inside_area?
  → игрок может ходить в main и во всех subAreas

Файл camera.rb
• update(player, game_map) использует area_bounds_for(player.x, player.y)
• Если area уже экрана (например 4×4 при 576×480) — центрирует её
• Если area больше экрана — клампит по границам


📐 Правила, чтобы код не превратился в кашу

#   Правило                                        Как соблюдать
1   Один редактор — одна папка                     Хочешь BattleEditor → Editors/BattleEditor/.
                                                     Не лезь в MapEditor/ или EventEditor/.
2   Partial-файлы для больших редакторов            MapEditorView = 11 partial по 100–400 строк.
                                                     EventEditorView = 7 partial. Каждый — за свою область.
3   Core — общий для всех                           Модели и сервисы в Core/. Любой редактор их использует.
4   MainWindow знает только IEditor                  Никаких ссылок на конкретные классы редакторов.
                                                     Только интерфейс.
5   Общение между редакторами — через Core          Не через прямые ссылки. EventEditor захочет карту —
                                                     вызовет MapJsonService.Load.
6   События для взаимодействия с оболочкой          Не пихать логику MainWindow в редактор.
                                                     Редактор кидает StatusChanged — MainWindow его ловит.
7   Отдельный Canvas — отдельный класс              Если редактор хочет свой рендер —
                                                     создаёт свой *Canvas.axaml. Не модифицирует чужой.
8   FullRedraw ≠ RedrawCanvas                       FullRedraw — только при смене карты (пересоздание
                                                     8192 Image). RedrawCanvas — на каждое изменение UI
                                                     (только оверлей). Критично для скорости.
9   subAreas — макс 10                               Индексы 0..9. Ссылки — по индексу.
                                                     Main всегда main, sub — всегда sub.
10  Формат JSON — читаемый                          Свой StringBuilder-форматтер в AreasService.Save.
                                                     Массивы в одну строку, объекты — разнесены.
