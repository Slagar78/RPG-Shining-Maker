📁 Формат JSON: Сохранение с табами

Мы отказались от WriteIndented и переписали сохранение вручную.
Теперь файлы сохраняются в точности как в C-программе (cJSON).

Пример entries.json:
[{
		"id":	0,
		"folder":	"Granseal",
		"name":	"Granseal",
		"music":	"assets/sounds/Track1.mp3",
		"music_volume":	0.8,
		"areas":	"data/maps/Granseal/areas.json"
	}, {
		"id":	1,
		"folder":	"map00"
	}]

Пример нового события в events.json:
{
	"type":	"counter",
	"x":	5,
	"y":	10
}

Правила:
• Используются табы (\t) для отступов.
• Нет склеивания в одну строку.
• Каждый элемент с новой строки.
• Игра на Ruby читает это без ошибок.
• Вложенные массивы (tiles, collision, collision2) пишутся горизонтально (сеткой), чтобы не растягивать файл на тысячи строк.


📐 Правила, чтобы код не превратился в кашу

#   Правило                                        Как соблюдать
1   Один редактор — одна папка                     TilesetImporter лежит в Editors/TilesetImporter/.
2   Partial-файлы для больших редакторов            MapEditor = 11 файлов, EventEditor = 7 файлов,
                                                     TilesetImporter = 4 файла. DatabaseEditor тоже делится на Views/.
3   Core — общий для всех                           Модели и сервисы в Core/. Любой редактор их использует.
4   MainWindow знает только IEditor                  Никаких ссылок на конкретные классы редакторов.
5   Общение между редакторами — через Core          Импортер вызывает MapJsonService.Save и EntriesService.Save.
6   События для взаимодействия с оболочкой          Редактор кидает StatusChanged — MainWindow его ловит.
7   Отдельный Canvas — отдельный класс              Если редактор хочет свой рендер — создаёт свой *Canvas.
8   FullRedraw ≠ RedrawCanvas                       FullRedraw — при смене карты, RedrawCanvas — на изменения UI.
9   subAreas — макс 10                               Индексы 0..9. Main всегда main, sub — всегда sub.
10  Формат JSON — читаемый                          Свой StringBuilder-форматтер с табами (\t). Массивы пишутся горизонтально.
11  Безопасность имен                               При импорте имена проходят транслитерацию (RU->EN).
12  Counter = невидимая логика                      В игре прилавок не блокирует диалог, а разрешает его сквозь себя (talk_through).
13  Базовая графика и Оверрайды                     Кружки (0-3) меняются только в блоксете (свойства тайла), 
                                                     квадраты (5-8) — только на карте (оверрайд). 
                                                     Коллизии хранятся в двух независимых массивах: collision (L1) и collision2 (L2).
14  Изоляция графики (Playtest)                     Для запуска из редактора без ошибок WGL используется Mesa (opengl32.dll) + llvmpipe.
15  Кинематографичный старт                         Заставка (Splash) ждет полной загрузки окна (событие Opened), затем плавно исчезает.
16  DatabaseEditor = MVVM                           Используется Binding, ObservableCollection и RelayCommand вместо ручного перерисовывания.
17  Два слоя коллизий                               В редакторе при активном L1 рисуем в collision, при L2 — в collision2.
                                                     Оверлей сетки на канвасе показывает коллизию активного слоя.
18  Единый источник истины (State)                  В игре BattleManager получает ссылки на @party и @start_inventory. Никаких копий.
19  SpellLevels                                     У заклинания один ID и массив levels. В редакторе — таблица уровней.
20  ActorBlocks                                     В actors.json плоский список. Редактор разворачивает Base + Promotions в один объект.
